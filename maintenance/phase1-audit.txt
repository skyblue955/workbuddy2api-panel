Official integration evidence (retrieved 2026-11-02)
https://open.workbuddy.cn/docs/openapi
https://open.workbuddy.cn/docs/third-party-app
Official platform documents registered third-party apps, user-authorized OAuth and scoped APIs, including credit redemption. It does not establish that the existing legacy /v2/chat/completions, daily-checkin or private reward-task endpoints are supported third-party APIs.
New internal/workbuddyopen connector follows the documented redemptions contract only: mutually exclusive single/dual code request with stable request_id, fixed HTTPS endpoint, per-call OAuth token, no persistence/automatic retry/redirect, bounded responses and redacted errors. This is a library foundation, not yet wired into UI/scheduler or end-to-end account verified. App registration, approved scope and user authorization remain prerequisites.
OAuth expiry examples differ between the official pages; future token management must use actual expires_in rather than hardcode documentation prose.

Reward inventory and unresolved boundaries
- Check-in/balance/gift/compensation/travel/growth calls remain legacy/private contracts; existing source comments are not proof of official support.
- panel/tasksweep.go accepts and claims reached progress; eligibility remains upstream. Claims are distinct from creating progress.
- scheduler activity and panel/autotask.go include manufactured telemetry; travel may adopt and accept agreements. These paths are not ordinary reward-only collection. This patch neither expands nor executes them. Follow-up must separate explicit eligibility-based claims from synthetic progress and gate legacy automation.
- tasks.go Accept All has an early return before mini-program-only pending tasks; record for later contract review, not an immediate private-task expansion.
- Invalid explicit realm normalization, global base override and body-read error propagation are follow-up local robustness items.

Acceptance limitations

Unit/mock results do not prove current real account API availability, official app approval, earned credit receipt or account status. Docker image build and remote GitHub Actions were not executed locally.
Independent review caught and corrected a non-200 redemption response-body close leak. A mistaken reviewer claim that OAuth scope belongs in the redemption JSON was rejected against the official contract; scope remains attached to authorization. Final review found no concrete blockers in this patch.
